# Фасет «CBD содержание»: две шкалы и формула диапазонов

Переносимая спека. Описывает, как считаются и рисуются чекбоксы
«Концентрация» (проценты) и «Общо, mg» (миллиграммы) в фильтре каталога.

Ничего в спеке не привязано к Vendure, Next или React: нужны только товары со
строковыми полями «сила» и «объём» и обычный фасетный фильтр.

---

## 0. Одно предложение

Это **одна грань каталога с двумя несводимыми шкалами**: проценты
перечисляются поштучно, миллиграммы режутся на диапазоны, и режутся не по
круглым числам, а по тому, где на полке лежат товары — заново на каждое
изменение любого другого фильтра.

---

## 1. Почему шкалы две

Магазин продаёт в разных форматах, и формат диктует, чем меряют силу:

| Что | Чем продаётся | Почему |
|---|---|---|
| Масло, паста | концентрацией — «20% CBD Oil» | европейский покупатель сравнивает бутылки по проценту |
| Крем, капсулы, желейки, вейп | общим содержанием — «CBD Face Cream 300mg» | процент крема — число, по которому никто не покупает |
| Американское масло | миллиграммами | на этикетке так написано |

**Одна шкала из них не получается ни в какую сторону.** Перевод процента в
миллиграммы и обратно требует объёма, а у банки капсул объёма нет — есть
штуки. Любая попытка свести к одному числу — это выдуманная цифра, которой
этикетка не заявляла.

Практическое следствие: **ось — свойство товара, а не категории.** Таблица
«категория → ось» верна ровно до первого американского масла в миллиграммах.

---

## 2. Модель силы

```ts
type StrengthAxis = 'percent' | 'mg'
type Strength = { axis: StrengthAxis; value: number }  // 10 = «10%», 300 = «300 mg»
```

### 2.1. Как определяется ось

**Сигнал — процент в собственном названии товара.** Не категория, не наличие
миллилитров.

```
если в title есть /(\d+([.,]\d+)?)\s*%/  →  ось 'percent'
иначе                                    →  ось 'mg'
```

Товар, не заявляющий содержания вовсе (конопляное масло без каннабиноидов,
цвет на вес), возвращает `null` и в грани не участвует **вовсе** — не считается
нулём.

### 2.2. Как считается значение

**Ось `percent`.** Значение берётся не из названия, а из арифметики
`мг / (мл × 10)`, округлённой до одного знака:

```
percentOf(product) = round( (мг / (мл × 10)) × 10 ) / 10
```

Название — только сигнал оси; цифра — из тех же данных, из которых её печатает
карточка товара. Причина ниже, в §10, ошибка 6.

Если объёма нет и посчитать не из чего — берётся цифра из названия как есть.

**Ось `mg`.** По убыванию приоритета:

1. миллиграммы, написанные в поле силы (`/(\d+([.\d]+)?)\s*mg/i`);
2. если в поле силы стоит процент, а в объёме — миллилитры:
   `round(процент × мл × 10)`;
3. иначе `null`.

**Процент считается только у жидкостей, меряемых в миллилитрах.** Деление
450 mg на «30 капсули» даёт число, которое не является концентрацией ничего —
именно так фильтр однажды предложил выбрать 0%, 0.1%, 0.3% и 0.6%.

### 2.3. Токен для адреса

```
percent → `${value}pct`   // 10pct, 0.5pct
mg      → `${value}mg`    // 300mg
```

Пишется словами, а не кодируется: отфильтрованный список должно быть можно
прочитать и переслать из адресной строки. И главное — **голое число не
годится**: `10` не отличает 10% от 10 мг, а обе цифры в каталоге есть.

Разбор токена строгий: `/^(\d+(\.\d+)?)(pct|mg)$/`, значение > 0, иначе `null`
и токен молча выбрасывается из запроса.

---

## 3. Счётчики: фундамент, без которого шкала не работает

Шкала миллиграммов режется **из счётчиков**, поэтому правило подсчёта — часть
формулы, а не соседняя тема.

**Грань считается против всех фильтров, кроме своего собственного.**

```
счётчики(грань) = tally( applyFilters(товары, …всё, except = грань) )
```

Две крайности, обе испробованы и обе неверны:

| Как | Что ломается |
|---|---|
| Считать по всему маршруту | На странице косметики предлагаются проценты, которых у кремов нет |
| Считать по текущей выборке | Галочки исчезают по мере проставления, вернуться нечем |

Внутри одной грани значения складываются по «или», между гранями — «и».

**Из этого следует главное свойство блока:** отметил категорию — шкала
миллиграммов пересчиталась и порезалась заново под то, что осталось. Полоса,
за которой ничего не стоит, не рисуется.

---

## 4. Шкала процентов: диапазонов не бывает

Перечисляется значение за значением, по возрастанию. Всегда.

**Почему.** Концентрацию в промежутках не указывают нигде — ни на упаковке, ни
в поисковой выдаче. «10% масло» — это вещь, «10–20% масло» — нет. Человек,
которому нужны 10%, отметит «10%», а «10–20%» прочитает как «нам всё равно».

Длина списка решается не группировкой, а раскладкой: короткие подписи идут в
две колонки (§8).

---

## 5. Шкала миллиграммов: формула

### 5.1. Правило словами

1. Читаем те цифры, которые **названы у товаров текущей выборки** (не из
   справочника, не из настройки).
2. Цифр мало (**≤ 6**) — каждая своим чекбоксом. Человеку, которому нужна
   тысяча, легче отметить «1000», чем «500–1000».
3. Цифр больше — соседние собираются в диапазоны, **но группируются по числу
   товаров, а не по расстоянию между цифрами**.
4. Строк не больше **5**.
5. Группа из одной цифры подписывается ею самой: «1000», а не «1000–1000».

### 5.2. Почему по числу товаров, а не по арифметике

Арифметика делит шкалу поровну и ставит границу там, где нет покупателей.
Дозировка, в которой лежит половина полки, обязана стоять отдельной строкой, а
редкий хвост наверху — делить одну.

Механика: цифра присоединяется к строящейся группе **только если это
приближает группу к её доле товаров**, а не удаляет. Ходовой размер
перескакивает долю сразу и остаётся один; тонкий хвост сходится в строку.

### 5.3. Алгоритм

```ts
type Tally  = { token: string; value: number; count: number }
type Bucket = { tokens: string[]; min: number; max: number; count: number }

const TARGET     = 5   // максимум строк
const LIST_UP_TO = 6   // до скольких показываем поштучно

function strengthBuckets(tallies, target = TARGET, listUpTo = LIST_UP_TO): Bucket[] {
  const sorted = tallies.filter(t => t.count > 0).sort((a, b) => a.value - b.value)
  if (sorted.length === 0) return []

  const single = t => ({ tokens: [t.token], min: t.value, max: t.value, count: t.count })

  // Коротко — читаем поштучно.
  if (sorted.length <= listUpTo) return sorted.map(single)

  const total = sorted.reduce((s, t) => s + t.count, 0)
  const share = total / target          // «справедливая» доля одной строки

  const buckets = []
  let current = null

  for (const entry of sorted) {
    // Закрывать группу можно, только пока впереди есть место под ещё одну.
    // Это и есть гарантия «не больше target строк».
    const room = buckets.length + 1 < target

    if (current !== null && room) {
      const joined = Math.abs(current.count + entry.count - share)  // если присоединить
      const closed = Math.abs(current.count - share)                // если закрыть сейчас
      if (joined > closed) { buckets.push(current); current = null }
    }

    if (current === null) current = single(entry)
    else {
      current.tokens.push(entry.token)
      current.max = entry.value
      current.count += entry.count
    }
  }

  if (current !== null) buckets.push(current)
  return buckets
}
```

Три места, где легко ошибиться при переносе:

- **`share` — постоянная величина `total / target`, а не остаток.** Первая
  версия пересчитывала долю от нераспределённого остатка и приклеила
  тысячемиллиграммовую дозировку к соседям по одному товару. Так делать нельзя.
- **`room` — единственный ограничитель числа строк.** Никакого `slice(0, 5)`
  в конце: обрезка потеряла бы цифры. Когда место кончилось, последняя группа
  просто вбирает весь остаток.
- **Сортировка внутри функции.** Счётчики приходят в произвольном порядке;
  шкалу можно читать только по возрастанию.

### 5.4. Разбор на примере

Полка: 250 (1 товар), 500 (1), **1000 (40)**, 1500 (1), 2000 (1), 2500 (1),
3000 (1). Всего 46 товаров, 7 цифр — больше шести, значит группируем.
`share = 46 / 5 = 9.2`.

| Цифра | Присоединить | Закрыть | Решение |
|---|---|---|---|
| 250 | — | — | начали группу, count 1 |
| 500 | \|1+1−9.2\| = 7.2 | \|1−9.2\| = 8.2 | 7.2 < 8.2 → присоединить, count 2 |
| **1000** | \|2+40−9.2\| = 32.8 | \|2−9.2\| = 7.2 | 32.8 > 7.2 → **закрыть**, начать новую |
| 1500 | \|40+1−9.2\| = 31.8 | \|40−9.2\| = 30.8 | 31.8 > 30.8 → **закрыть**, 1000 осталась одна |
| 2000 | \|1+1−9.2\| = 7.2 | \|1−9.2\| = 8.2 | присоединить |
| 2500 | \|2+1−9.2\| = 6.2 | \|2−9.2\| = 7.2 | присоединить |
| 3000 | \|3+1−9.2\| = 5.2 | \|3−9.2\| = 6.2 | присоединить |

Итог: `250–500 (2)`, `1000 (40)`, `1500–3000 (4)`. Ходовая тысяча получила
свою строку с обеих сторон, редкий хвост сошёлся в одну.

### 5.5. Числа 5 и 6 — и почему они маленькие

- **5 строк.** Рядом стоит колонка процентов, а колонка выше соседней читается
  как более важная, хотя не важнее. И проще: список, до конца которого не
  дочитывают, не фильтрует ничего.
- **6 поштучно.** Колонка процентов при двух колонках раскладки укладывается
  примерно в шесть строк; выше шести цифр охватить взглядом уже нельзя, и
  начинается группировка.

Оба вынесены параметрами функции — при переносе подгоняются под свою
раскладку, но подгоняются **вместе**: `listUpTo` заметно больше `target` даёт
скачок высоты блока на ровном месте.

## 6. Нажатие на диапазон

Диапазон — это один орган управления, стоящий за несколькими токенами.

```ts
function toggledAll(values, group) {
  const all = group.every(v => values.includes(v))
  if (all) return values.filter(v => !group.includes(v))   // снять ровно эти
  return [...values, ...group.filter(v => !values.includes(v))]  // добавить недостающие
}
```

- `selected` у диапазона — когда выбраны **все** его токены.
- Счётчик диапазона — **сумма счётчиков его цифр**, чтобы строка обещала ровно
  то, что покажет сетка.
- В адрес уходят отдельные цифры (`strength=300mg,350mg`), а не диапазон.
  Это важно: полка меняется, границы диапазонов пересчитываются, и сохранённая
  ссылка на «400–600» после завоза нового товара означала бы уже другой набор.

Значение диапазона как ключа списка — `mg:${min}-${max}`, оно живёт только в
разметке.

---

## 7. Что не показывается

Три уровня одного правила «орган управления показывается, когда может изменить
то, что на экране»:

1. **Опция с нулевым счётчиком не рисуется** — это не фильтр, а тупик.
   Исключение: уже выбранная опция остаётся всегда, иначе покупатель теряет
   единственный способ отменить то, что поставил.
2. **Колонка, в которой не осталось опций, не рисуется.** Выбрали масла —
   миллиграммовая колонка исчезла сама; выбрали косметику — исчезла
   процентная; на всём каталоге стоят обе.
3. **Грань с одной опцией не рисуется.** Если у всего в выборке одна и та же
   сила, галочка не даёт выбора: поставить — ничего не изменится, не ставить —
   тоже.

---

## 8. Оформление

- **Заголовок грани** — «CBD содержание». Под ним две подколонки со своими
  подзаголовками: «Концентрация» и «Общо, mg».
- **Подзаголовок на миллиграммовой колонке — не украшение, а единственное
  место, где написана единица.** В строках стоят голые числа. Единица,
  повторённая в каждой строке, на 320 пикселях переносилась на вторую строку.
  У процентов наоборот: `%` стоит в каждой строке, потому что заголовок
  «Концентрация» единицей не является.
- **Две шкалы стоят одна под другой, а не рядом.** Рядом они были одинаковой
  высоты, а высота у них разная: дюжина концентраций против четырёх полос
  содержания — и половина грани стояла пустой.
- **Внутри колонки короткие подписи идут в несколько колонок**, и сколько
  именно — отвечает контейнер, а не число:
  `grid-template-columns: repeat(auto-fit, minmax(130px, 1fr))`.
  Фиксированные две колонки на боковой панели 216px давали по 34px на подпись,
  и десктоп читал `Cap / sule / s`. Пол в 130px оставляет узкой панели одну
  колонку, а полноэкранной шторке телефона — две.
- **Подписи подколонок — на ступень мельче заголовка грани.** Вложенное
  никогда не крупнее того, что его содержит.

---

## 9. Проверки, которые надо перенести

Формула проверяется без каталога и без браузера — на списках `{value, count}`:

1. Горстка цифр перечисляется поштучно, а не превращается в диапазоны.
2. Цифры выходят по возрастанию, в каком бы порядке ни пришли.
3. Цифра с нулевым счётчиком строки не получает.
4. При многих цифрах: строк не больше `target`; **все цифры сохранены, ни одна
   дважды**; каждая группа — непрерывный отрезок соседей; `min ≤ max`; счётчик
   группы равен сумме её цифр; группы идут вверх.
5. Дозировка, в которой лежит большая часть полки, получает отдельную строку.
6. Пустой вход — пустой выход.

Отдельно, на уровне разбора силы: перевод «мг + мл → процент» с одним знаком
после запятой; товар без содержания даёт `null`; токен туда-обратно
(`10pct` → `{percent, 10}` → `10pct`).

---

## 10. Ошибки, за которые уже заплачено

Самая ценная часть переноса. Каждая была в бою.

1. **Неподвижные полосы «до 500 / 500–1000 / 1000–2000 / над 2000».** Врали
   трижды: полоса «500–1000» стояла там, где на полке ровно одна цифра — 750;
   две ходовые дозировки прятались в одну строку; и полосы не двигались, когда
   посетитель сужал выборку.
2. **Группировка по расстоянию между цифрами.** Делит шкалу поровну и ставит
   границу там, где нет покупателей.
3. **Доля, считаемая от остатка, а не от целого.** Приклеила ходовую тысячу к
   соседям по одному товару.
4. **Процент, посчитанный делением мг на число капсул.** Фильтр предлагал 0%,
   0.1%, 0.3%, 0.6%. Процент бывает только у жидкости в миллилитрах.
5. **Процент, округлённый до целого.** Бальзам 200 mg в 50 мл стал «0%», и
   фильтр предложил его как выбор. Нужен один знак после запятой.
6. **Два округления одного числа.** Карточка считала процент сама, фильтр —
   сам, и страница разошлась со своим же фильтром. Считать один раз, одной
   функцией, обеим.
7. **Ось, выбранная по таблице категорий.** Верно до первого американского
   масла в миллиграммах.
8. **Ось, выбранная по наличию миллилитров.** Крем 300 mg во флаконе 200 мл
   встал на полку как «0.2%».
9. **Счётчики по всему маршруту.** Страница косметики предлагала фильтровать
   кремы по процентам, которых у кремов нет.
10. **Счётчики по текущей выборке.** Галочки исчезали по мере проставления.
11. **Голое число в адресе.** `10` не отличает 10% от 10 мг.
12. **Две шкалы рядом.** Разная высота, половина грани пустая.
13. **Единица в каждой строке.** Перенос на вторую строку на 320.
14. **Фиксированные две колонки.** `Cap / sule / s` на узкой панели.

## 11. Что при переносе придётся своё

| Место | От чего зависит |
|---|---|
| Правило определения оси | От того, как у вас названы товары. Наш сигнал — процент в названии. Если название не несёт силу — нужно поле на товаре, а не угадывание |
| Разбор «мг» и «мл» из строк | У нас это поля-строки движка (`strength`, `volume`). При нормальных числовых полях весь §2.2 схлопывается в чтение полей |
| `TARGET` / `LIST_UP_TO` | От высоты соседней колонки в вашей раскладке |
| Пол в 130px | От ширины вашей панели фильтров и длины подписей в вашем языке |
| Подписи и `{min}–{max}` | Из вашего набора текстов, с языками |

**Что переносится без изменений:** §5.3 целиком (формула), §6 (`toggledAll`),
§3 (правило счётчиков) и §9 (проверки).
