# Как начинать следующий сайт

Этот файл написан на восьмидесятой правке, а нужен был на первой. Он о том,
в каком порядке класть — не о том, что класть: рецепты лежат в
`styles/tokens.css`, `styles/primitives.module.css` и `docs/rules.md`, и
переезжают целиком.

---

## Главная ошибка, ради которой файл и заведён

Правила были написаны раньше фундамента, на который ссылаются.

`CLAUDE.md` с первого дня требовал: размер — из шкалы `--fs-*`, отступ — из
шкалы `--sp-*`. Ни одной из шкал в коде не было. Каждая сессия честно шла их
спрашивать, не находила и ставила число. Через месяц число стояло 153 раза у
размеров и 483 у отступов — и это не неряшливость исполнителя, это правило,
ссылающееся в пустоту.

**Правило, у которого нет реализации, хуже отсутствующего правила.**
Отсутствующее видно сразу; ссылающееся в пустоту создаёт ощущение, что
фундамент есть, и его никто не проверяет.

Поэтому порядок ниже начинается не с компонентов.

---

## Порядок

### 1. Полдня на фундамент, до первого блока

Три шкалы и пять примитивов. Ничего из этого нельзя отложить «на потом,
когда станет видно»: к тому моменту, когда станет видно, в коде будет
четыреста чисел, и введение шкалы превратится в отдельный проект.

Три шкалы — это ответы на три разных вопроса, и путать их нельзя.

---

#### Цвет — это роли, а не оттенки

Не «серый-3» и «зелёный-9», а **чем вещь работает**:

| роль | что это |
|---|---|
| `--page` | пол страницы |
| `--surface` | поверхность карточки, листа, всплывающего окна |
| `--ink` | чернила: основной текст |
| `--ink-dim` | приглушённые чернила: подпись, пояснение, второстепенное |
| `--ctrl` | фон кнопки и поля |
| `--hover-ctrl` | то же под курсором |
| `--accent` | акцент: то, что зовёт нажать |
| `--on-accent` | текст поверх акцента |
| `--line` | волосок разделителя |

Имя оттенка говорит, как вещь выглядит. Имя роли говорит, зачем она нужна. И
только второе переживает смену темы: тёмная тема — это подмена девяти
значений в одном месте, а не переписывание всех файлов. По той же причине
тёмная полоса на светлой странице делается подменой ролей на её границе:
всё внутри по-прежнему написано «чернилами», просто здесь чернила светлые.

Оттенки при этом никуда не деваются — они лежат отдельной лестницей
(`--sage-1 … --sage-12`), и роли ссылаются на них. Но в компонент попадает
роль, никогда оттенок.

#### Размер — это типографика

Лестница ступеней от самой мелкой строки до заголовка героя:

```
--fs-2xs  --fs-xs  --fs-sm  --fs-md  --fs-base  --fs-lg
--fs-xl   --fs-2xl --fs-h3  --fs-h2  --fs-h1
```

Ключевое: каждая ступень — **пара чисел**, а не одно. Нижний конец нарисован
от телефона, верхний от десктопа, между ними `clamp()` тянет плавно. Одно
число на всю ширину — это либо мелко на мониторе, либо огромно на телефоне,
третьего не бывает.

Взять десктопную шкалу и ужать её линейно тоже нельзя. На узком экране
контраст заголовка к телу обязан **сжиматься** — примерно с 4:1 до 2–2.3:1,
— иначе заголовок блока на телефоне сравнивается с заголовком страницы, и
читатель перестаёт понимать, что главнее. Поэтому концы ступени рисуют
порознь: телефонный от телефона, десктопный от десктопа.

Наклон не выдумывают, а считают. Для концов на 560 и 1080:

```
наклон = (макс − мин) / 5.2          свободный член = мин − (макс − мин) × 1.0769

--fs-xl: clamp(16px, 13.85px + .38vw, 18px)
          ^ мин      ^ прямая         ^ макс
```

Читается так: не меньше 16, не больше 18, между 560 и 1080 идёт линейно.
Новой ступени число на глаз не назначают — считают по этой же формуле.

**Ступенька размера на брейкпоинте — всегда дефект**, даже когда выглядит
безобидно. `calc(var(--h2-size) * .8)` в медиазапросе давал 26px на 821-м
пикселе и 20.8px на 820-м: пять пикселей на одном пикселе ширины. Если
телефону нужен другой размер — это нижний конец ступени, а не отдельное
правило.

#### Ритм — это расстояния

Всё, что в CSS называется `padding`, `gap`, `margin`: отступ внутри карточки,
просвет между карточками, воздух между разделами, отбивка заголовка от
текста. К типографике отношения не имеет.

```
--sp-1  4px          оптика: под скруглением штриха
--sp-2  8px          внутри контрола
--sp-3  10 → 12      между строк группы
--sp-4  14 → 16      поле карточки
--sp-5  18 → 22      поле крупной карточки
--sp-6  22 → 28      между блоками внутри раздела
--sp-7  28 → 36      заголовок к содержимому
--sp-8  36 → 48      между полками
--sp-9  48 → 64      между разделами
```

Ритм — самая недооценённая из трёх, и именно она решает, выглядит страница
собранной или слепленной. Разница между 22px и 24px не видна **по одной
штуке** — а по всей странице видна сразу: это разница между «здесь есть
система» и «здесь каждый блок делал свой человек». Ровно поэтому чисел и
накапливаются сотни: каждое по отдельности выглядело разумным.

У ритма есть тонкость, которой нет у размера: **он течёт неравномерно.**
Мелкие ступени стоят намертво — 4px под скруглением штриха это 4px и на
телефоне, и на мониторе, волосок не бывает «телефонным». Крупные ходят на
треть себя: 64px воздуха между разделами на десктопе читаются как воздух, те
же 64 на телефоне — это треть экрана, потраченная на ничто. Поэтому ступень
тем подвижнее, чем она больше.

Числа для шкалы берут **из вёрстки, а не из головы**: считают, какие отступы
уже стоят, и строят ступени по ним. Шкала, не покрывающая того, чем
пользуются, ничего не заменяет — она добавляется третьим способом делать то
же самое, и числа продолжают появляться рядом с ней.

#### Пять примитивов раскладки

Шкалы отвечают, каким быть; примитивы — как лежать.

| | что делает |
|---|---|
| `stack` | столбик с одним ритмом: отступ ставится **между** соседями, а не каждому |
| `cluster` | строка, которая переносится: пилюли, теги, ряд кнопок |
| `switcher` | две колонки, становящиеся одной **без медиазапроса** |
| `rail` | полоса, уходящая в прокрутку, с прилипанием |
| `prose` | мера набора: строка длиннее 75 знаков теряется на возврате |

Настраиваются переменными (`--stack`, `--switch-at`, `--rail-gap`), а не
вариантами класса: вариант пришлось бы заводить под каждое новое число, а
переменная принимает любую ступень шкалы — и ступень видна в том же месте,
где раскладка.

`switcher` стоит объяснить отдельно, потому что он снимает целый класс
проблем. Его порог сравнивается с шириной **родителя**, а не окна:

```css
.switcher > *{ flex-basis: calc((var(--switch-at, 640px) - 100%) * 999) }
```

Пока контейнер уже порога, скобка положительна, основа заведомо больше ряда
— каждый ребёнок забирает строку. Стал шире — скобка отрицательна, основа
схлопывается в ноль, дети делят ряд. Медиазапрос не нужен вовсе, и один и
тот же блок ведёт себя правильно в рельсе, в сетке и во всю ширину.

### 2. Проверки-храповики с первого коммита

Не с восьмидесятой правки. Храповик не требует чинить накопленное — он не
даёт расти новому, и в этом вся разница между «долг сокращается» и «долг
растёт».

* `check:css` — по файлам: число вместо ступени, лишний брейкпоинт,
  пропорция без потолка.
* `check:craft` — по **отрисованной** странице: мера текста уже своей
  колонки, цель нажатия меньше пальца, контраст ниже порога, слипшиеся
  блоки, обрезанный своим же блоком текст, заглушка на витрине. Дефект,
  который заказчик находит глазами, в диффе выглядит безупречно — его видно
  только на странице.

  Страницы для него берёт `routes.mjs` — из ДЕРЕВА МАРШРУТОВ, а не из
  списка в файле проверки: список, набранный рукой, не растёт вообще.
  И проходов три, потому что тема и указатель — тоже измерения: как есть,
  с `colorScheme: 'dark'` и с `hasTouch` на планшетных ширинах.
* `check:open` — каждая страница дерева открывается в `next dev`. Часть
  проверок фреймворк делает только там: сайт может собираться и отдаваться
  на проде, а в разработке падать — обе отрисованные проверки этого не
  увидят, они ходят по собранному.
* `check:urls` — обещанное открывается, открытое обещано. Обе половины: и
  мёртвый адрес в карте сайта, и страница, которую никто не обещал и которая
  при этом не сказала о себе `noindex`.
* `sweep` — снимок на каждой ширине от 320 до 1600. У агента нет окна,
  которое можно потянуть за угол, а ломается всегда на промежуточной
  ширине.

Проверка, падающая с первого дня, живёт до первого «давай отключим».
Поэтому — храповик, а не порог.

### 3. Три брейкпоинта, назначенные заранее

И ставятся только там, где меняется **смысл**: две колонки становятся одной,
панель становится выдвижной. Меняется величина — это шкала.

Ступенька размера на брейкпоинте — всегда дефект, даже когда выглядит
безобидно: `calc(var(--h2-size) * .8)` в медиазапросе давал 26px на 821-м
пикселе и 20.8px на 820-м. Пять пикселей на одном пикселе ширины.

### 4. Компонент меряет контейнер, а не окно

С самого начала, по умолчанию: `container-type: inline-size` и `@container`.
Тогда «мёртвой зоны 700–1050» не возникает как класс проблемы — не бывает
ширины, про которую блок не знает. Один и тот же компонент стоит в рельсе, в
сетке и во всю ширину; окно про его ширину не знает ничего.

Отсюда же `switcher`: две колонки, становящиеся одной, — это про ширину
родителя, а не про ширину экрана, и медиазапроса не требует вовсе.

### 5. Сначала данные, потом раскладка

Что настоящее, что заглушка, откуда приходит, кто правит. Раскладка,
написанная под тексты, которых ещё нет, ломается на настоящих — а ломается
она у заказчика, после сдачи.

Отдельно: **граница ответственности**. Как устроено и как выглядит — работа
исполнителя. Что написано и что стоит на витрине — работа заказчика.
Заглушка `[NAME]` под отзывом — дефект наполнения: о нём сообщают, его не
выносят с витрины.

### 6. Язык — адресами, а не в браузере

Если сайт не английский: `/bg`, `/en` как настоящие адреса, с первого дня.
Перевод, применяемый в браузере, отдаёт поисковику английский HTML —
болгарский магазин, которого в болгарском поиске нет. Переделывать это
позже дороже, чем сделать сразу: адреса тянут за собой маршруты, карту
сайта, канонические ссылки и хлебные крошки.

## Как поставить набор на новую машину

Набор лежит внутри cbdin.bg, а cbdin.bg — на GitHub. Значит, **ничего не
привязано к одному диску**: с любого ноутбука, из любой пустой папки —

```
git clone --depth 1 https://github.com/IgorAIdev/CBDin.bg.git /tmp/kit-src
node /tmp/kit-src/tools/kit.mjs .
rm -rf /tmp/kit-src
```

Первая строка тянет исходник во временную папку, вторая раскладывает набор в
ту, где вы стоите, третья убирает временное. Дальше:

```
npm i -D sharp serve && npx playwright install chromium
```

### Свой репозиторий — когда надоест клонировать cbdin.bg

Три шага, все на GitHub:

1. Новый пустой репозиторий, например `craft-kit` (приватный или открытый —
   открытый нужен, если захотите ставить его через `npx`).
2. В пустой папке выполнить команду выше — набор ляжет туда.
3. `git init && git add . && git commit -m "стартовый набор" &&
   git remote add origin <адрес> && git push -u origin main`

После этого первая команда сокращается до клонирования `craft-kit`, а
обновлять набор — тем же `node tools/kit.mjs` из cbdin.bg в клон craft-kit.

## Что переезжает файлами

| файл | что в нём |
|---|---|
| `styles/tokens.css` | три шкалы, роли цвета, резервы под фиксированные полосы |
| `styles/primitives.module.css` | пять примитивов раскладки и общие контролы |
| `tools/check-css.mjs` | храповик по файлам |
| `tools/check-craft.mjs` | храповик по отрисованной странице |
| `tools/routes.mjs` | список адресов из дерева маршрутов и данных |
| `tools/check-open.mjs` | открывается ли каждая страница в разработке |
| `tools/check-urls.mjs` | обещанное открывается, открытое обещано |
| `tools/sweep.mjs` | съёмка по ширинам |
| `docs/rules.md` | переносимые правила И1–И20, каждое с дефектом, из-за которого заведено |
| `CLAUDE.md` | восемь запретов вёрстки и правила работы |
| `tools/kit.mjs` | сборщик: `npm run kit ../new-site` собирает всё перечисленное |

`docs/rules.md` — единственный файл, переживающий конец сессии. Всё
остальное можно вывести заново; его — нет.
